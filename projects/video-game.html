C-Based Video Game

C, MSPM0G3507 LaunchPad · Nov. 2023 – Apr. 2024

Overview

A two-player soccer game — modeled after the mobile game Head Soccer — that my partner Ryan Kehtar-Navaz and I built on a TI MSPM0G3507 LaunchPad for our embedded systems course. Each player controls their character's jump height with a slide-pot and kicks with a button, played out on a 160×128 ST7735R LCD with sound effects driven off an onboard DAC. It's the project on here that's most fun to actually play.

  • Real-time physics engine (gravity, jump arcs, character-vs-character and character-vs-ball collision, wall/goal detection) running in a 30 Hz timer interrupt, decoupled from LCD rendering in the main loop
  • Two analog slide-pots read via ADC for continuous jump-height control, plus two debounced push-buttons for kicks
  • Kick/goal sound effects played back through a 5-bit DAC at 11 kHz off digitized audio samples baked into C arrays
  • Full English/Spanish bilingual UI — menus, countdown, score, and win/tie screens
  • Built on top of the course's ST7735 LCD, clock, timer, ADC, and DAC drivers; the game engine, physics, collision handling, and UI flow are ours

Architecture

The design splits cleanly into two halves that never touch each other directly: a 30 Hz interrupt service routine (TIMG12_IRQHandler) that owns all the physics — sampling the slide-pots, reading the buttons, integrating position and velocity, and resolving collisions — and the main loop, which owns everything that touches the LCD. A single semaphore flag (positionflag) hands control from one to the other each frame. That split exists for a real reason: SPI writes to the LCD are slow enough that doing them inside the physics ISR would stall the timing the game engine depends on, so the rule (there's a comment that says it outright) is no LCD output in interrupt service routines.

Sound works the same way the physics does but simpler: Sound_Start hands a pointer into one of the pre-recorded sample arrays (Kick, Goal) to a SysTick interrupt running at 11 kHz, which streams one byte per tick out to the DAC until the sample runs out — so triggering a sound effect from game logic is just a matter of pointing the ISR at a different buffer.

Physics Snippet

Jump physics and ball-wall collision response, called every frame from the 30 Hz ISR: 

void JumpLeft(void){
    if (leftb == 1){
        jumpflagl = 1;
        vxl = 5;
    }
}

void gravityl(void){
    if (jumpflagl == 1){
        vxl = vxl - 1;
        leftb = 0;
        if (xl <= 10){
            vxl = 0;
            xl = 10;
            jumpflagl = 0;
        }
    }
}

void checkcollisionwall(void){
    if(xBall <= 15){
        collisionflag = floorcollision;
    }
    if(xBall >= 128){
        collisionflag = wallcollision;
    }
    if(yBall >= 160){
        collisionflag = wallcollision;
    }
    if(yBall <= 0){
        collisionflag = wallcollision;
    }
}
